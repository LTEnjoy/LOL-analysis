# 01 产品说明：内战战绩网站

## 1. 用户需求与已确认决策

用户和朋友们打 5v5 英雄联盟内战，需要一个记录和分队工具。

已确认的产品决策：

- 只做一个 HTML 文件，别人打开就能看。
- 纯前端，无后端、无构建步骤、无外部依赖。
- 谁都可以录入，结果保存在当前浏览器。
- 功能包含：英雄 / 位置、自动分队、记录胜负。
- 数据存储使用浏览器 localStorage，不使用服务器。
- 分享方式：导出“带数据 HTML”快照，发到群里。
- 历史约束：原机器要求文件放 `D:\tmp`、不放用户主目录；当前机器改为项目内 `data\`，脚本不再写用户主目录。

用户后续希望减少手动录入，已研究 API 方案；官方 Riot API 不适用，国服本机 LCU 接口可行。LCU 细节见 `02_lcu_integration.md`。

## 2. 页面与功能

单文件：`website/lol_stats.html`，深色中文界面，响应式桌面/移动端。

### 排行榜

- 汇总卡片：总对局、玩家数、最高评分、最高胜率。
- 排行榜表格：玩家、场次、胜/负、胜率、KDA、综合评分。
- 最近对局历史：日期、胜方、双方阵容、每人 KDA、英雄、位置。
- 支持编辑 / 删除历史对局。

### 录入对局

- 选择红蓝双方各 5 名玩家，共 10 人。
- 每人填写 K / D / A、英雄、位置。
- 选择日期、胜方（红/蓝）、备注。
- 同一玩家不能重复上场。
- 保存后立即更新排行榜。
- 编辑历史对局时复用同一表单。

### 自动分队

- 选择 10 名启用玩家。
- 按综合评分做蛇形选秀，再做两两交换优化。
- 显示红蓝双方阵容和队伍评分差。
- 支持点击一名玩家、再点另一队玩家手动交换；交换后实时重算差值。

### 玩家

- 添加玩家（昵称最长 20 字符）。
- 启用 / 停用玩家。
- 删除玩家。
- 只有启用玩家会进入录入和分队候选。

### 数据

- 导出 JSON：完整状态，便于备份/换电脑。
- 导入 JSON：**替换**当前数据；会做规范化和校验。
- **检测并同步客户端**：调用本机 `127.0.0.1:8765` 的桥接服务；先检测客户端进程/登录状态，再拉取全部 5v5 峡谷自定义对局并按 gameId 合并（`mapId=11` + `gameMode=CLASSIC`，海克斯大乱斗/练习模式/不足 10 人跳过）。本地桥未启动时会尝试通过 `lolsync://` 自动拉起，失败时显示「启动本地服务」按钮。
- **导入 JSON 文件（兜底）**：选择 `lcu_sync.py` 输出的 JSON（或旧版裸数组）；规则与自动同步相同。
- 合并语义：按 `m_lcu_<gameId>` 去重，按名字匹配/自动创建玩家，只追加、不覆盖。状态区显示新增场次、新增玩家、跳过重复/无效原因。
- 指标回填：同步/文件导入后，对已存在但缺 13 个评分字段的对局，按 gameId + 选手名把指标补进去；不增删对局、不改胜负/队伍/手改的 KDA，已有指标的对局跳过。补完后立即重算评分与排行榜。
- 旧桥提示：若本次返回的对局全都没有评分字段（通常是常驻的 `lcu_server.py` 还是旧版本），状态区会明确提示这些对局仍按旧公式计分，并提示重启本地桥。
- 导出带数据 HTML：把当前状态写进新 HTML 的 seed，生成可分享快照；会清空合并状态提示。
- 清空所有数据。
- 显示本地存储是否可用。

### 其他

- 同一浏览器多个标签页通过 `storage` 事件同步。
- 页面加载时比较 seed 与 localStorage 的 `updatedAt`，较新的生效。
- 当前发布文件的 seed 是 `null`，即首次打开是空数据。

## 3. 数据模型

localStorage key：`lol-custom-stats-v1`

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-05T08:00:00.000Z",
  "players": [
    {
      "id": "p_xxx",
      "name": "玩家昵称",
      "active": true,
      "createdAt": "2026-11-01T10:00:00.000Z"
    }
  ],
  "matches": [
    {
      "id": "m_xxx",
      "date": "2026-11-01",
      "createdAt": "2026-11-01T13:00:00.000Z",
      "winner": "red",
      "note": "",
      "participants": [
        {
          "playerId": "p_xxx",
          "team": "red",
          "kills": 10,
          "deaths": 2,
          "assists": 5,
          "champion": "法外狂徒",
          "position": "打野"
        }
      ]
    }
  ]
}
```

约束：

- 每场必须正好 10 名参与者，红 5、蓝 5，且玩家不重复。
- `team` / `winner` 只能是 `red` 或 `blue`。
- `position` 只能是：`上单`、`打野`、`中单`、`ADC`、`辅助`、`未填写`；导入时空字符串或非法值会被清空。
- `champion` 最长 20 字符。
- `date` 必须是 `YYYY-MM-DD`，否则导入时回退为当天。
- `kills/deaths/assists` 会做非负整数截断。

## 4. KDA 与综合评分

单场 KDA：

```js
kda = (kills + assists) / Math.max(deaths, 1)
```

### 4.1 多维评分（LCU 对局，2026-11-06 起）

不判断位置、不使用玩家历史；每局 **10 人内**把指标换成百分位（0–1），因此时长、顺风局、英雄强弱自动抵消。需要该局 10 人都有完整指标，缺任何一项就回退 4.2。

| 维度 | 权重 | 指标（同局百分位） |
|---|---|---|
| 影响力 | 4 | KDA、参团率、助攻占比、治疗占比、分均控制、伤害占比、推塔伤害占比、目标伤害占比 |
| 发育 | 3 | 分均补刀、分均经济 |
| 视野 | 2 | 分均视野分、分均买真眼、分均排眼 |
| 目标 | 1 | 目标伤害占比、推塔伤害占比 |

```js
perf  = 0.5 * Σ(维度权重 × 维度均分) / Σ维度权重 + 0.5 * 最强三项均值;
score = perf * 100;                    // 不含胜负
playerRating = Σscore / 场次;          // 总评 = 各局算术平均，不做收缩
```

场次与总评的关系：

- 场次只作分母，没有任何先验分或收缩；1 场和 27 场同一套规则。
- 加一场新对局 = 加入它的单局分、分母 +1。
- 场次只影响两处展示逻辑：① 排行榜「按综合评分」排序时，同分则场次多者在前；② 「最少场次」筛选（全部 / ≥3 / ≥5）只过滤显示，不改分数。
- 小样本不会被拉向均值，所以 2~3 场的玩家可能因单局波动排名很高或很低，这是有意的。

说明：

- 维度内各指标等权；KDA 在影响力里只占 1/8，但影响力本身权重最高，整体以 KDA 为主导。
- 「最强三项」让辅助（视野）、坦克（承伤/治疗）、C 位（影响力/发育）各有得分路径。
- 指标缺时长时用非分钟数值；旧手录对局完全没有指标。
- 实测 27 局：分数与胜负相关系数 ≈ 0.34；低补刀高视野（辅助型）与常规打法均分差约 4 分。

### 4.2 旧公式（手录对局 / 缺指标数据回退）

```js
SHRINK_GAMES = 5;

winRate  = (wins + 0.5 * SHRINK_GAMES) / (games + SHRINK_GAMES);
kdaAvg   = (kdaSum + 4.0 * SHRINK_GAMES) / (games + SHRINK_GAMES);
kdaScore = Math.min(kdaAvg / 8, 1);
rating   = (winRate * 0.5 + kdaScore * 0.5) * 100;
```

- 一个玩家只要有任何一局带指标，就只按 4.1 计算，不与 4.2 混算。
- 完全没有指标数据的旧玩家仍用 4.2。

## 5. 存储、导入与分享

### 本地存储

- 使用 `localStorage`，key 为 `lol-custom-stats-v1`。
- 数据只在当前浏览器 / 当前设备有效。
- 同一浏览器多标签页通过 `storage` 事件同步。
- 浏览器禁用本地存储时，页面会提示“数据仅在本次会话有效”。

### seed 机制

HTML 中有：

```html
<script type="application/json" id="seed-data">null</script>
```

- 导出带数据 HTML 时，会把当前状态序列化并注入这个 script。
- 加载时如果 seed 的 `updatedAt` 比 localStorage 新，则使用 seed。
- 否则使用 localStorage。

### 导入

- 导入 JSON 会**替换**当前状态，不是合并。
- 导入时会规范化玩家和对局，丢弃不合法的对局（例如不是 10 人、不是 5v5）。
- 导入后如果启用玩家不超过 10 人，会自动勾选到自动分队候选。

### 自动同步（LCU）

- 入口：数据页「检测并同步客户端」。
- 先请求本地桥 `GET /api/status`：
  - 本地桥未运行 → 尝试 `lolsync://` 自动拉起；若浏览器拦截或启动失败，显示「启动本地服务」按钮，并提示运行 `install_protocol.py` / `lcu_server.py`；
  - 客户端未启动 → 提示先启动并登录；
  - 客户端已启动但未登录 → 提示确认登录；
  - 正常 → 显示召唤师名并继续。
- 再请求 `POST /api/sync`（带 `X-LCU-Sync: 1`），服务返回与 `lcu_sync.json` 相同的信封。
- `lcu_sync` / 本地桥只输出 `mapId=11` + `gameMode=CLASSIC`、10 人、红蓝各 5 的对局；海克斯大乱斗（`mapId=12` / `KIWI`）、练习模式、人数不足 10 的对局全部跳过。
- 拿到结果后复用 `mergeLcuGames()`；0 场时提示“没有可用的 5v5 峡谷自定义对局”。
- 超时：状态 20 秒，同步 180 秒；请求异常/服务 5xx 都在状态区显示原因。
- 文件方式打开（`file://`）时连接固定地址 `http://127.0.0.1:8765`；用本地桥托管网站时同源直连。

### 合并导入（LCU）

- 入口：数据页「导入 JSON 文件」。
- 输入：`lcu_sync.py` 的 `{source, fetchedAt, games:[...]}`，或裸数组（旧 `lcu_custom_games.json`）。
- 对局 ID：`m_lcu_<gameId>`；已存在则跳过。
- 玩家：名字 trim + 忽略大小写匹配；找不到自动创建启用玩家。
- 校验：每场 10 人、红蓝各 5、名字不重复、胜方有效；无效场次整场跳过。
- 提交：先构造完整结果，至少一场有效才一次性追加并 `saveState()`；不修改现有数据。
- 不改变 `schemaVersion`、localStorage key 和现有替换式导入。

### 导出 HTML

- 克隆当前文档。
- 注入 seed JSON（对 `<` 做转义，避免 XSS）。
- 清空动态渲染容器、重置 tab。
- 触发下载新 HTML 文件。
- 朋友打开新文件即可看到快照数据。

### 分享限制

浏览器安全限制不允许网页直接改写自己所在的 HTML 文件。因此：

- 当前浏览器的数据在 localStorage。
- 要分享，必须导出带数据 HTML。
- 导出后原文件不会自动更新；需要重新导出。

## 8. 已知限制

- 没有账号/权限系统；拿到 HTML 的人都能改。
- 数据是浏览器本地的，不是实时共享数据库。
- 导入 JSON 是替换而不是合并；自动同步/合并导入是独立入口。
- LCU 自动同步需要先运行本地桥 `scripts/lcu_server.py`；桥未启动时只能离线导出再导入。
- 本地桥是常驻进程，**升级 `lcu_sync.py` 后必须重启桥**才会生效；否则仍返回不带评分字段的旧格式（页面会提示）。
- 同步仍由按钮触发，不会在每局结束后自动执行。
- 玩家按召唤师名匹配；改名会被当成新玩家，同名无法区分（没有 PUUID）。
- 最近 101 局窗口之外的对局只能靠 `.rofl`（会过期）或 EOG watcher。
- 综合评分是启发式，不是官方 MMR/ELO。
- 位置字段依赖玩家选择；LCU 同步默认不写位置。
- 跨设备分享需要手动导出 HTML。
- 如果浏览器清理站点数据，localStorage 会丢失；建议定期导出 JSON/HTML 备份。
